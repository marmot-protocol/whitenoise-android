Refs #2779 and #2785. This foundation changes test tooling only. The subsequent
Android behavior PR remains a draft with an independent local-before-network slice.
No tracker/child closure, native throughput repair, merge or release is claimed.

## Provenance and method

Implementation started from current master `ee00de179` in an isolated worktree.
[Exact library/APK/probe provenance](attachment-fixture-2026-10-01/provenance.json)
records MarmotKit 0.11.0, MDK `946e0547485c9a2c393c2048ec3a968fd50fb441`,
emulator-5554 API30 arm64, isolated measurement package and artifact digests.
No physical-device app was installed, removed or cleared.

The loopback HTTP server stores each request, ciphertext socket write and terminal
outcome in an independently committed SQLite ledger outside the native/app process.
Generated peer identities publish a genuine 1 KiB TXT through the packaged native
library. Android resolves the receiver's own native attachment-history identity,
then reads exact plaintext through its production resolver. The endpoint is made
unavailable (503) after cold completion. Ten subsequent reads assert both Android
caches empty. A further read closes/reopens the native database at the same path.
This tests native-runtime reopen, not app process restart, whole-device offline,
navigation, a protected background worker or external Open/Save handoff.

Each successful run must have exactly one upload, one GET/HEAD acquisition request,
a completed ciphertext response, and 1,040 uploaded/downloaded ciphertext bytes.
There must be zero additional acquisition requests for all eleven retained reads.
Counts exclude control requests; payload-write bytes exclude error JSON, HTTP
headers and TCP/link traffic. Failed attempts stay in their individual run ledger.
Java/native memory is sampled absolute heap usage every 10 ms plus initial/final
samples, not allocation deltas or guaranteed maxima. Latency includes sampler
lifecycle. Other host builds were active, so variability remains visible.

## Controlled reference budgets fixed before candidate measurement

These are fixture-specific regression ceilings, not production release targets:

| Phase/metric | Candidate requirement |
| --- | --- |
| Exact plaintext | All 12 reads equal the generated bytes |
| Cold acquisition | Exactly 1 GET/HEAD, one complete 1,040-byte ciphertext body |
| Ten retained reads + native reopen | Zero additional GET/HEAD or ciphertext payload writes |
| Cold resolver latency | Each sample <= 1,500 ms |
| Cache-free retained/native-reopen latency | Each sample <= 150 ms |
| Sampled Java peak | <= 32 MiB for every measured phase |
| Sampled native peak | <= 128 MiB for every measured phase |
| Saturated Android gate | Canonical local read completes while all 3 unrelated permits remain held; zero explicit demand |

The baseline calibration is three sessions per distribution and ten retained reads
per session. Cold/reopen have only three samples per distribution: report medians
and maxima, no p95. Retained has thirty observations, including within-session
correlation; report nearest-rank p95 with raw samples. No cold-throughput gain is
claimed without a phase-specific gain beyond measured variability.

## Validation and remaining outcomes

The final shared fast gate passes workflow/shell checks, Zapstore instrumentation
compilation and ktlint. Both isolated APK/test variants build and all six actual
emulator sessions pass. All 13 host contracts pass. Hosted CI and CodeRabbit remain
pending after draft publication.

Host contract tests exercise real sockets, exact held-prefix cancellation without
EOF, disconnect detection, explicit release, Range/If-Range, validator restart,
unknown length, HEAD, uploaded ciphertext, persistent ledger restart and private
path/size bounds. Relay tests cover HTTP1.1 masked WebSocket negotiation, publish,
filter and reconnect. Runner tests cover failure-ledger preservation, independent
cleanup and rejection of physical-device serials before adb access.

The fixture started with failures before qualification: HTTP1.0 WebSocket upgrade
was rejected by the native SDK, and borrowing the sender's receipt failed received
history lookup. Both were repaired at the fixture owner; no generated timeline row
or retained source was substituted. Only final fully qualified runs enter this
baseline. A first Gradle test worker stalled without results; final focused runs
use an isolated 2 GiB test heap. Failed build/test attempts are not counted as PASS.
