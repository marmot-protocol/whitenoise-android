## Independently reproduced Android race

The caller checks its cache before joining the shared download owner. That miss
can become stale before admission: a preceding owner can publish and retire,
or a queued request can become cached before it gets a slot. The old admission
path starts network work without rechecking either cache tier.

Two deterministic tests failed on the original code: the late caller made two
downloads instead of one, and the queued cache hit made one download instead of
zero. The fix rechecks the existing memory and authenticated encrypted-disk
caches after gate admission, including a second memory lookup after a suspended
disk miss. It adds no cache, telemetry, network retry, or concurrency increase.

The focused suite also covers shared callers, account isolation, failed-owner
retry, queue priority/cancellation, transfer ownership, plaintext resolution,
and main-thread confinement. The reduction in redundant download calls is
verified by those tests; the component timings above do **not** measure the
speedup from this fix or establish this race as the cause of prior field tails.

Receipt-to-visible UI latency, distinct-image albums, stalled-locator failover,
internal transport/crypto phases, signed candidates, and representative network
and OS qualification are outside this component result. See the
[probe instructions](performance.md#isolated-media-component-probe) for safe
reproduction and explicit opt-in requirements.
