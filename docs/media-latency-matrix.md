# Synthetic media latency matrix

This procedure is the first controlled measurement slice for Android #2785. It
does not use a personal White Noise account, file, or installed package. The
test creates an identity and a private group under the isolated
`dev.ipf.whitenoise.android.medialatency` package, uploads generated bytes to
the configured media service, downloads them, verifies byte equality, then
removes its local store. Encrypted remote fixtures follow the service's normal
retention policy. Run it on a disposable emulator or dedicated test device.
The first emulator results are in [the preliminary baseline](media-latency-preliminary-baseline.md).

## Matrix and boundaries

| Class | Bytes | Repetitions | Guard |
| --- | ---: | ---: | --- |
| Small | 64 KiB | 20 | `allowMediaSizeMatrix=true` |
| Medium | 1 MiB | 5 | `allowMediaSizeMatrix=true` |
| Large | 8 MiB | 3 | `allowMediaSizeMatrix=true` |
| Near the app's 32 MiB send ceiling | 30 MiB | 1 | Also set `allowNearLimitMediaProbe=true` |

Each repetition times a bounded in-memory import copy, one MarmotKit upload,
and one cold `downloadMedia` call. It samples Java and native allocated heaps
every 50 ms plus the operation endpoints. The reported heap peaks are absolute
sampled values, so a shorter spike can be missed. `payload_bytes_total` is the
known plaintext payload count, **not network traffic**; `network_bytes` stays
`null` until a vetted byte-count source or controlled server fixture exists.
The current test bypasses the Android plaintext cache and does not measure a
real document provider, UI first progress, process recreation, installer
dispatch, or receipt-to-visible pixels. The existing
`measureSyntheticImagePhases` and `measureLocalImagePhasesWithoutNetwork`
remain separate component checks for backlog/native phases and cache/decode.

Run the same APKs for each declared network condition: unshaped Wi-Fi, a
controlled constrained Wi-Fi fixture, and offline-to-online recovery. Do not
label a run constrained unless the bandwidth/latency/loss settings and the
actual network path were verified outside the app. Repeat on the exact
candidate and baseline heads; report failure counts, not only successful
percentiles. One near-limit result is a correctness and memory observation,
not a stable p95 estimate.

## Guarded emulator run

Build from a committed, clean source checkout so `source_sha` identifies the
actual test code. The init script changes only this local
build's dev application ID. Verify the app and test APK metadata name the
isolated package before installing. The commands below install in place and
run instrumentation directly; they never uninstall either package.

```sh
test -z "$(git status --porcelain)"
./gradlew --init-script scripts/media-latency.init.gradle \
  :app:assembleDevZapstoreDebug :app:assembleDevZapstoreDebugAndroidTest \
  -Pandroid.injected.build.abi=arm64-v8a
python3 - <<'PY'
import json
from pathlib import Path
for path, expected in [
    (Path('app/build/intermediates/apk/devZapstore/debug/output-metadata.json'),
     'dev.ipf.whitenoise.android.medialatency'),
    (Path('app/build/intermediates/apk/androidTest/devZapstore/debug/output-metadata.json'),
     'dev.ipf.whitenoise.android.medialatency.test'),
]:
    actual = json.loads(path.read_text())['applicationId']
    assert actual == expected, (path, actual)
PY
adb -s emulator-5554 install -r -t \
  app/build/intermediates/apk/devZapstore/debug/app-dev-zapstore-arm64-v8a-debug.apk
adb -s emulator-5554 install -r -t \
  app/build/intermediates/apk/androidTest/devZapstore/debug/app-dev-zapstore-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w -r \
  -e class dev.ipf.whitenoise.android.media.MediaAttachmentLatencyProbe#measureSyntheticSizeMatrix \
  -e allowMediaProbe true -e allowMediaSizeMatrix true \
  dev.ipf.whitenoise.android.medialatency.test/androidx.test.runner.AndroidJUnitRunner \
  > /private/tmp/wn-2785-media-probe.txt
```

Add `-e allowNearLimitMediaProbe true` only for the 30 MiB case on a test
environment with sufficient heap, storage, and upload capacity. A failed
sample remains a failed run. For physical instrumented runs through Gradle,
always pass `-Pandroid.injected.androidTest.leaveApksInstalledAfterRun=true`;
the direct `am instrument` command above does not uninstall the app.

Create a machine-readable report with `scripts/media_latency_report.py`. It
accepts only fixed phase labels and numeric values from the test output,
rejects unexpected fields, and requires full source and APK digests plus a
coarse device/network class. It still writes a report with `complete: false`
when instrumentation fails, then exits nonzero. Keep the raw test output
private; it is not needed in a pull request.

```sh
python3 scripts/media_latency_report.py /private/tmp/wn-2785-media-probe.txt \
  --source-sha "$(git rev-parse HEAD)" \
  --mdk-sha "$(sed -n 's/^mdk-sha=//p' app/src/main/marmotkit/MARMOT_VERSION)" \
  --app-apk-sha256 "$(shasum -a 256 app/build/intermediates/apk/devZapstore/debug/app-dev-zapstore-arm64-v8a-debug.apk | cut -d ' ' -f 1)" \
  --test-apk-sha256 "$(shasum -a 256 app/build/intermediates/apk/androidTest/devZapstore/debug/app-dev-zapstore-debug-androidTest.apk | cut -d ' ' -f 1)" \
  --device-class emulator --network-profile wifi_unshaped \
  --output /private/tmp/wn-2785-media-report.json
```

The report contains aggregate timing, sampled heap peaks, native phase
histogram intervals, payload counts, and outcome counts. Native histogram
buckets are not exact per-operation durations. Compare like-for-like network
fixtures and exact APKs before setting budgets or attributing a dominant
delay. This synthetic component run cannot establish that the user's reported
staging download is fixed.
