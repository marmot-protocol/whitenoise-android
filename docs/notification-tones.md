# Notification tones

Ding is a single bright bell-like tone; Pulse is a lower ascending pair. Both are original additive synthesis, with no recorded or third-party samples. `scripts/generate_notification_tones.py` is the editable source and reproduces the committed mono 48 kHz PCM16 WAV files. Source and audio assets are licensed under the repository’s GNU Affero General Public License v3. The generated envelope bounds the peak below −6 dBFS, fades in over 8 ms and out over 30 ms, and keeps each sound below one second. A measured signal check does not replace listening or device playback qualification.

Permanent `ding-v1` and `pulse-v1` content URI tokens identify immutable public audio. The read-only provider resolves resource IDs at access time; channel URIs do not embed build-specific resource IDs. Keep these assets and tokens available across upgrades and restore. Changing a waveform requires a new token and resource; retain the original v1 bytes for channels that already selected them. Literal URI tokens and exact v1 audio digests are regression-tested. Only new DM, group and mention categories default to Ding. Existing OS channels, including silence and user customizations, retain their settings.

The Notifications screen previews sounds and explicitly copies them into the system’s notification-sound collection. Import is separate from choosing a sound. Users open Android’s category, conversation or person settings to select a tone, their own sound, or None. Conversations and people explicitly assigned their own sound retain that sound when a global category changes. Channels without an explicit sound override can follow their effective source; new channels clone that source. No app preference pretends to override an existing channel. Category labels show Off when app/category/channel-group notifications are blocked, Silent for low-importance or soundless channels, and the current tone otherwise. Device-wide notification volume, Silent mode and DND still govern playback and previews.

Imported copies remain in shared Notifications storage, including after uninstall. After reinstall or some restores, Android may no longer attribute an old copy to this installation. Without broad media permission it can be invisible to this app, so adding sounds can create another named copy in the picker. A selected copy the app can no longer read can show the generic “Android sound” label. Existing inaccessible copies are never deleted or overwritten; re-add the tones and explicitly choose the current copy in Android if playback is unavailable. Repeated imports reuse exact owned bytes and repair picker metadata. A changed same-name file is preserved. A failed new write removes only that attempt’s pending row. A retained complete pending row can be finalized on retry. An incomplete pending row is preserved and a retry creates a suffixed copy; Android can expire the abandoned pending row. Public copies can be deleted by the user; re-add them and choose again in Android if the selected copy disappears. Android/OEM pickers control whether the tones appear directly or under My Sounds. Supported-device qualification must confirm discoverability and actual playback, plus DND/silence and upgrade behavior; no in-app preview establishes those results.
