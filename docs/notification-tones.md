# Notification tones

Ding is a single soft, bassier tone at 220 Hz with gentle harmonics, a rounded attack and a 0.8-second decay. Pulse is an ascending pair. Both use original additive synthesis with no recorded or third-party samples. `scripts/generate_notification_tones.py` reproduces the committed mono 48 kHz PCM16 WAV files. Source and audio assets use the repository’s GNU Affero General Public License v3. Ding peaks at about −3.7 dBFS; Pulse remains below −6 dBFS. Both fade to silence within one second. Signal measurements do not establish device playback quality.

Permanent `ding-v1` and `pulse-v1` content URI tokens identify the bundled tones. The softer Ding replaces the earlier bright waveform at both existing Ding URI forms, so channels already set to bundled Ding play the replacement after upgrade. Pulse retains its original audio. The read-only provider resolves resource IDs at access time; channel URIs contain no build-specific resource IDs. Regression tests pin both tokens and current audio digests. New DM, group and mention categories default to Ding. Existing OS channels retain their selected URI, silence and custom settings.

Previously imported sound-picker copies are separate files and keep their earlier audio. Import Ding again to add the softer version, then select that copy explicitly in Android settings. Import preserves a same-name file with different bytes.

The Notifications screen previews sounds and explicitly copies them into the system’s notification-sound collection. Import is separate from choosing a sound. Users open Android’s category, conversation or person settings to select a tone, their own sound, or None. Conversations and people explicitly assigned their own sound retain that sound when a global category changes. Channels without an explicit sound override can follow their effective source; new channels clone that source. No app preference pretends to override an existing channel. Category labels show Off when app/category/channel-group notifications are blocked, Silent for low-importance or soundless channels, and the current tone otherwise. Device-wide notification volume, Silent mode and DND still govern playback and previews.

Imported copies remain in shared Notifications storage, including after uninstall. After reinstall or some restores, Android may no longer attribute an old copy to this installation. Without broad media permission it can be invisible to this app, so adding sounds can create another named copy in the picker. A selected copy the app can no longer read can show the generic “Android sound” label. Existing inaccessible copies are never deleted or overwritten; re-add the tones and explicitly choose the current copy in Android if playback is unavailable. Repeated imports reuse exact owned bytes and repair picker metadata. A changed same-name file is preserved. A failed new write removes only that attempt’s pending row. A retained complete pending row can be finalized on retry. An incomplete pending row is preserved and a retry creates a suffixed copy; Android can expire the abandoned pending row. Public copies can be deleted by the user; re-add them and choose again in Android if the selected copy disappears. Android/OEM pickers control whether the tones appear directly or under My Sounds. Supported-device qualification must confirm discoverability and actual playback, plus DND/silence and upgrade behavior; no in-app preview establishes those results.

New channels use a stable versioned tone URI ending in White Noise Ding or White Noise Pulse so Android can display that name. The original one-segment ding-v1 and pulse-v1 URIs remain readable aliases with the current bundled audio. Existing channels keep their selected URI and can retain the old token label; choose the named tone again in Android to update that selection.

Both URI forms are permanent: `content://<package>.notification-tones/ding-v1/White%20Noise%20Ding` and `content://<package>.notification-tones/pulse-v1/White%20Noise%20Pulse`, plus the original `content://<package>.notification-tones/ding-v1` and `content://<package>.notification-tones/pulse-v1`. Both Ding forms serve the softer replacement; both Pulse forms retain the original Pulse audio.
