[ ] **MED-034 — Received media downloads in the background** — With a disposable receiving account, set Settings → Data Usage so images, videos, audio and files download automatically on Wi-Fi, connect to Wi-Fi and press Home so White Noise's Activity is stopped. From a second device, send into a chat the receiver never opens: an image, an animated GIF, a short video, a voice note, an audio file and a small document, as one album and as separate messages. Wait two minutes without opening the app, then open the chat with the network turned off. Repeat in a muted chat, for a receiving account that is not the active one, after force-stopping White Noise from Settings and reopening it once, and with the app killed by the system rather than force-stopped. Then turn videos off for Wi-Fi, switch to mobile data with the defaults, tap Stop automatic downloads, sign the account out, and fill the device until Android reports low storage, each time sending a fresh album. Also send media while on Wi-Fi with videos enabled, then turn videos off before Android runs the queued download. Afterwards read the `DMAttachmentReceipt` and `DMAttachmentWorker` lines in logcat. → **Expected:** With the network off, every enabled type in the unopened chat renders and plays from local data, including in the muted chat and for the inactive account, and opening the chat starts no new network transfer. A type disabled for the current network, a stopped backlog, a signed-out account and low storage leave those attachments remote with a manual Download control, and a type turned off before its queued download runs is not fetched. Media received while White Noise was force-stopped is not downloaded until the app runs again; that is outside this check. Each receipt with attachments logs one `attachment_receipt_scheduled` line with queued and held counts and held types only, and a queued download that policy now holds back logs `attachment_work_policy_deferred` with its type only; neither line names an account, chat, message, file name or attachment index. Received media never raises a sound, vibration or extra notification beyond the message's own notification.
