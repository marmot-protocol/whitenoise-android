1. [ ] **SET-061 — Link a new device** — This needs the build on two devices or emulators and a disposable local-key account. Sign in to the same account on both. On the new device open Settings, Account, Devices and choose Link this device. On the device already signed in, wait for the chat list's notice that a new device is asking to link, tap Review, compare the emoji and choose Link device; on the new device choose They match. Repeat, each time from a new device that is signed in but not yet linked (remove it from Devices on the approving device, then remove the account from it and sign in again), and each time do one of: choose Not now on the approving device; choose Cancel on the new device; let the request time out; tap an action twice quickly; close the request with Back; press Back on the new device's step and reopen it from Devices; send the approving app to the background before the request arrives and bring it back after it timed out; type a device name and, under Options, turn a choice off before Link device; type a device name and clear it again before Link device; enter a device name longer than 64 bytes. Repeat with a second profile active on the approving device, and with an account that signs through an external signer app. Repeat in dark, AMOLED, RTL and at the largest font size, with TalkBack, and with notification permission denied. → **Expected:** The new device says to open White Noise on another device and keep both apps open, then shows seven emoji four over three, each with its name under it, with They match and Cancel; every name is the same size and the cells in a row are the same height; at the largest font size the names shrink together so each stays whole, a two-word name such as Light Bulb breaking at its space only when it cannot fit on one line, never inside a word or behind an ellipsis. The request never opens over the app by itself: the approving device's chat list shows one notice, A new device is asking to link to your account, with Not now and Review, and only Review opens the request. Link device stays disabled for about a second after the emoji appear. The approving device then shows the same seven emoji in the same order with a Device name field, an Options row, Link device and Not now; the empty field shows New device, the name the device gets when none is typed, and Add to all my chats and Bring chat history, both on, appear only after Options is opened. Linking without typing a name or opening Options leaves both choices on, and the new device appears in both rosters as New device; a typed name is the one both rosters show, a name typed and cleared again, or one made only of spaces, goes back to showing and sending New device, and choices changed under Options are the ones applied. TalkBack reads each emoji with its position, for example "1 of 7". After both confirm, the new device says it is linking and only says This device is linked once linking has finished; the approving device says it is waiting for the new device and then that the new device is linked. Both devices then list each other under Devices. An action that fails says so on the step itself. Not now, Cancel, a timeout and a mismatch each end with their own message and link nothing; Try again starts a fresh attempt. A second quick tap submits nothing extra. Back closes the step or the request without cancelling or declining it, and Devices offers the way back in while linking is in progress. A request that expired in the background is shown as ended, never as a fresh request, and no notification is posted for a link request. A too-long name says so under the field and disables Link device, with Options open or closed. If another device finishes the request, Done or Close still works. Closing the checking step before the emoji arrive returns the request to the chat list's notice, and Review there shows its comparison; it does not reopen by itself. Not now on the chat list's notice hides it without answering the request. With another profile active, the chat list's notice names the profile that received the request; its Review opens the profile notice, whose Review switches to it and shows Checking the new device… with only Not now until that profile has read the request again, then the comparison, and Not now only hides the notice. A settled request stops offering Review for another profile. An external-signer account is told linking isn't available yet and is offered no link action. Nothing is clipped at the largest font size or in RTL. After Link device, the approving device says it approved the device and that joining usually takes under a minute, until it says the new device is linked. On the new device, an empty chat list says This device is linked for the first minutes after linking, explaining that existing chats are added by the other devices and that a new one can be started, instead of No chats. A chat another of the account's devices added this one to can arrive as an invitation; it never names the account itself as the inviter, it is never accepted without a tap, and Accept opens it as an ordinary chat. Turn off Bring chat history, lock and unlock the approving phone, then inspect Options before approving. The same request keeps the choice off and a different request starts with fresh choices. On the requesting device switch profiles while waiting. A locally started request cancels before this device submits They match. Switch after submitting They match and the confirmed link continues. A plain switch shows no link error. Leaving the screen with Back alone keeps the request available. With chat joins outstanding, use double text size and a short split-screen window. Scroll to New Chat and verify it opens the new-chat flow.
